Getting started

What is Talos AI agent?

Talos is an open-source, self-hosted AI agent that takes instructions through terminal chat or Telegram and can use tools for real work. A language model proposes each tool call; a separate deterministic kernel decides whether it is allowed, needs human approval or must be denied. Talos is an agent application, not Talos Linux or Cisco Talos. Start with the field manual or inspect the source on GitHub.

What can I use Talos for?

Use it to inspect a project, search and organise local notes, run permitted maintenance commands, prepare reports or delegate a bounded coding task to a configured Claude or Codex worker. The tools and host access available depend on your setup and permissions. The Command Hall shows a recorded session, not a live connection to anyone's agent.

How do I install Talos on macOS or Linux?

Follow the installation guide: inspect the Bash installer, install the signed release, configure your identity and model, then start terminal chat. Talos requires Python 3.11 or newer. The installer verifies the release and runs its tests; it does not start the agent automatically. A separate Pinokio launcher is also available; check the release it currently pins.

Can Talos run on a Raspberry Pi or a VPS?

Yes. Talos runs on Linux, including Raspberry Pi, as well as macOS. The agent and the model are separate: a Pi can run Talos while a configured provider supplies inference. Running a large model locally needs enough memory and compute for that model. Self-hosting does not imply that every model fits on a Pi. See model setup.

Can I use Talos as a self-hosted Telegram AI agent?

Yes. Configure your own Telegram bot and explicitly allow your identity. Talos fetches messages by long polling; the Telegram channel does not need a public webhook. Follow the Telegram setup instructions. Keep one service polling each bot token to avoid competing consumers.

Your models. Your costs.

Does Talos work with Ollama and local models?

Yes. You can configure Ollama as the model provider and run inference on hardware you control. Local inference avoids cloud-provider charges for those model calls, but hardware and electricity still cost money. Tool quality depends on the model; the permission kernel remains separate from it. Read the Ollama and model guide.

Can I use Claude or Codex with Talos?

Yes. Talos supports configured model providers and CLI integrations, including Claude through Claude Code, and bounded Claude and Codex coding workers. Reasoning and delegated coding are distinct roles. You must provide supported, valid access for the integration you choose; availability, usage limits and subscription eligibility are determined by that provider. Talos does not grant a model subscription or repair expired credentials by itself.

Is Talos free? Do I need Vercel or a Talos subscription?

Talos is MIT-licensed open-source software with no Talos subscription fee. Vercel or a paid gateway is not required. You pay for any cloud models, hosting or other services you choose; local models use your own hardware. A configured provider may have its own plan or usage charges. See the MIT licence.

Does /eval make every model faster?

No. /eval is a local classification and preflight diagnostic, not a faster model or a VPS inspection. It can classify a request without a model call, but that does not mean it has answered the request or executed a task. Actual response time depends on the model, context, network and required tools. A near-zero classification time is not an end-to-end speed benchmark.

The terms of the grant

Do I have to approve every action individually?

No. When offered for an attended task, Allow once approves the pending action, Allow this task covers eligible approval-required steps of that current task, and Always allow creates a standing rule for the exact action. A task approval is not a blanket grant for future tasks. Each tool call still goes through the kernel, and a hard denial cannot be turned into permission by the model. See the approval choices.

What does the deterministic permission kernel actually do?

It evaluates the proposed tool, arguments, derived targets and applicable policy before execution. The executor requires a capability tied to the approved call. The model cannot issue that capability itself. An audit trail records decisions and outcomes. This is an enforcement boundary, not a promise that the model never makes mistakes. Read the kernel explanation and the adversarial test documentation.

Does self-hosting mean my data never leaves my machine?

No, not automatically. Your selected model provider receives the context sent to it; external tools and Telegram also involve their configured services. Local inference through Ollama keeps those model calls on the host you configure, but it does not make unrelated network tools offline. Review providers, tool permissions and data flow for your deployment. Never put credentials or private runtime data in a public fork.

Can Talos work while I am away?

Talos supports scheduled and background work under an unattended ceiling. Actions that still need a human grant are refused or reported, rather than silently approved. Capabilities available in an attended conversation do not automatically carry over to unattended work. See the operation guide before relying on a scheduled workflow.

What happens if an agent or tool fails?

Inspect the recorded outcome rather than relying only on the model's summary. Talos includes stop controls, event inspection and recovery features such as undo for supported file changes. Undo is not a universal reversal of messages, remote operations or other external effects. Keep independent backups and test recovery for your own workload.

Judge the work

How should I compare Talos with IronClaw, OpenClaw or Hermes?

Compare the same task, model, host resources and permission scope. Measure completed outcomes, operator effort, latency and recovery, not just stars or test counts. Talos focuses on a readable deterministic capability kernel and scoped approvals; other projects may suit different integrations or workflows. We do not claim a universal winner. Read the documented comparison and check each project's current source for its own capabilities.

Is Talos production-ready?

Talos is in beta. Automated tests and signed releases are evidence for specific checks, not a guarantee of error-free operation. Review the beta operator contract, validate your own workflows and keep a rollback path. Experimental Computer adapters have separate qualification requirements; a source implementation is not a ready-to-use VM.

How can I star, fork or contribute to Talos?

Visit Talos on GitHub and star it if you want to keep track of the project. Fork the repository to experiment, follow the contribution guide, or open a reproducible issue. Helpful contributions include installation reports, clearer documentation and regression tests. Share only sanitised examples, never tokens, private logs or personal configuration.
