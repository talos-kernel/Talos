CASE STUDY / NETWORK BOUNDARY

One allowed address
must stay one.

A host can resolve to both an allowed address and an unlisted one. Checking only for the presence of an allowed address silently widens the permission.

The named-network exception requires every resolved address to satisfy the rule. These are illustrative addresses, not deployment data.

PROPERTY / NO MIXED-ANSWER BYPASS
answers = [allowed_address, unlisted_address]

# Every answer must satisfy the exception.
# One unlisted answer refuses the fetch.
guard_url(...)  # raises UrlRefusedError

CASE STUDY / CREDENTIAL BINDING

The right key.
Only the right route.

When a provider credential is missing, selection must fail before a request is built. Another provider's key is never a fallback.

The regression checks use different credentials for different providers and inspect the actual request headers.

PROPERTY / NO CROSS-PROVIDER CREDENTIAL
requested_provider = "openai-api"
configured_keys = ["anthropic"]

# Expected: refuse before network activity.
requests_sent = 0
credential_in_error = False

THE LIMIT OF THE EVIDENCE

A green run is
a starting point.

A passing suite means these known cases still produce their expected outcomes in the tested environment. It does not prove that all vulnerabilities have been found.

New models, integrations, deployments and attack shapes can expose gaps. A useful report includes the exact version, environment, action and observed result.
