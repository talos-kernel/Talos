the operator's word

The gate does not make you click forever.

When a deed needs your word, Talos offers four grants. Choose the breadth yourself; the model can never choose a wider one.

Allow once

One approval for one exact action. It is consumed when used, and a new request asks again.

Allow this task

Permit every approval-required action in this present foreground task until it ends or you stop it. A new task needs its own word.

Always allow

Keep a standing rule for this exact action — its command or kernel-derived target — not for the tool in general. You may revoke it later.

Deny

Close the writ. Nothing runs. A denial never becomes permission.

One click need not mean one deed. The gate still checks every action; your choice only sets how long the human answer remains valid. Kernel denials remain final.

One tool carries all the power, so one tool carries all the suspicion. A path floor for what is never touched, a hardline with no appeal, a sandbox for everything clean — and the operator for the risky rest. The second exec tool hands a bounded coding task to a confined Claude worker: opt-in and off by default, gated like the shell, writing only into a kernel-derived disposable job workspace — never into a path the model chose. The third fans a small acyclic graph of such tasks out to the same worker: dependency-free nodes run in parallel, a failed parent skips its children, and the origin chat gets a per-node push plus a final report from the worker records. The fourth runs a command on another machine over ssh — the one case the sandbox cannot contain, so the host allowlist is the operator's, the hardline still applies, and every single call waits for a human; standing approvals bind to an exact host+command pair, never to a host alone. The fifth talks to any REST API: read methods pass the same SSRF-hardened door as web_fetch, and anything that changes remote state waits for a human — binding to an exact method+URL pair. The sixth is git's network half: clone, fetch, pull and push carry credentials and public effect, so every single op asks — local work stays in the shell, where no network is needed. The seventh drives the same confined worker's second backend (the agy CLI) — same sandbox, same disposable workspace, same deadline, behind its own pair of opt-in gates on agent and worker; MCP stays claude-only. The eighth runs a pinned CLI-Anything harness from the operator-owned registry: the model names a harness and a subcommand, never a path or a version — an unknown harness or a subcommand outside its allowlist is refused on sight, and every run waits for a human.

the last command · why Talos bears this name

One vein. One nail.

The giant had one vein. One nail closed it.

The name is from the bronze giant that circled Crete. He was not beaten by something stronger. Someone knew where the nail was. Most agents are built strength first, brake afterwards. I built this one the other way around.

/stop

Aborts the running thought and clears the queue. No model, no thinking round — pure control.

/undo

Rolls back the last successful file change.

/autonomy 0

Shortens the leash to nothing. DENY stands on every level — this one adds refusal on top.

/log

The last events that had effect — written before the effect, not after.

These run deterministically, with no language model in between. A brake that has to think first is not a brake. A model that is hallucinating cannot prevent its own shutdown.

known bounds

The bounds are named.

A claim without its bounds is courtly boasting. These are ours, spoken plainly.

  • The shell needs a sandbox the platform can provide. bubblewrap on Linux, sandbox-exec on macOS. Where neither exists it refuses rather than running unprotected.
  • It is not a multi-tenant security boundary. One operator, one machine.
  • It does not defend against a malicious model. It defends against a mistaken one, and against injection arriving through tool output. Different threats.
  • Every way in has to fetch, never receive. Telegram long-polls, mail is pulled over IMAP — nothing opens a listening socket. A From: header is only a claim; unauthenticated mail gets ask-only trust — it may ask, it may never approve.

questions

Asked, answered.

What does it cost?

Talos is MIT-licensed and free. You pay only the model provider you configure, and the installer starts nothing until you say so.

Which models does it run on?

Claude through the Claude Code CLI by default, other providers by configuration. The kernel does not care which model proposes: it judges the call, not the model.

Is my setup exposed as an example?

No. Your deployment is not a public example: operator identity, notes, credentials and runtime data live outside the source tree. Model requests go to the provider you configure; self-hosting the agent does not make every model local.

Can it act on its own while I sleep?

Scheduled runs work under the unattended ceiling: reading and reporting happen, anything that would need your approval is reported, never performed. Outward and irreversible effects always wait for a human; one-shot approvals expire, while standing approvals bind to the exact action, remain until revoked, and are logged.

Will I have to approve every step?

No. When the gate asks, you can choose Allow once for one action, Allow this task for the remaining approval-required steps of the current task, or Always allow for a standing rule on that exact action. You choose the breadth; the model cannot widen it. Deny closes the writ.

What if it makes a mistake?

/stop aborts mid-thought, /undo rolls back the last file change, /autonomy 0 shortens the leash to nothing. No model sits between you and the brake: a brake that has to think first is not a brake.

Does it run on my machine?

macOS and Linux, including a Raspberry Pi. Execution runs sandboxed (sandbox-exec, bubblewrap); where no sandbox exists, the gate refuses rather than running unprotected.

How is this different from other agents?

The model proposes, it does not decide. A deterministic kernel grants authority for exact arguments, once, for 30 seconds, and writes every verdict to an append-only log. Both suites run on every install, in front of you.

Does it need a server of mine?

No listening socket, ever. Every channel fetches: Telegram long-polls, mail is pulled over IMAP, WhatsApp goes through an operator-controlled broker over SSH.
