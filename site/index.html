This is what the agent can do today. Each line tells you how it works, so you can verify it yourself.

delegate_code

Hands a bounded coding task to a confined Claude worker that builds, runs the tests and, with browser: true, drives a browser inside the same sandbox. Double opt-in, off by default, writing only into a kernel-derived disposable workspace.

completion push

When a delegated job finishes, fails or times out, the origin chat gets a short factual message built from the worker record, never model prose.

MEDIA:

A tag in the agent's own reply sends a generated file as a real chat attachment: kernel-derived roots only, capped at 20 MB and 4 files, and tool output can never forge one.

/blueprints

Installable automations in plain language: "every morning 08:30", never cron syntax. An installed blueprint is an ordinary schedule entry; the unattended ceiling applies unchanged.

One tool carries all the power, so one tool carries all the suspicion. A path floor for what is never touched, a hardline with no appeal, a sandbox for everything clean — and the operator for the risky rest. The second exec tool hands a bounded coding task to a confined Claude worker: opt-in and off by default, gated like the shell, writing only into a kernel-derived disposable job workspace — never into a path the model chose. The third fans a small acyclic graph of such tasks out to the same worker: dependency-free nodes run in parallel, a failed parent skips its children, and the origin chat gets a per-node push plus a final report from the worker records. The fourth runs a command on another machine over ssh — the one case the sandbox cannot contain, so the host allowlist is the operator's, the hardline still applies, and every single call waits for a human; standing approvals bind to an exact host+command pair, never to a host alone. The fifth talks to any REST API: read methods pass the same SSRF-hardened door as web_fetch, and anything that changes remote state waits for a human — binding to an exact method+URL pair. The sixth is git's network half: clone, fetch, pull and push carry credentials and public effect, so every single op asks — local work stays in the shell, where no network is needed. The seventh drives the same confined worker's second backend (the agy CLI) — same sandbox, same disposable workspace, same deadline, behind its own pair of opt-in gates on agent and worker; MCP stays claude-only.

emergency interface · provenance of the name

One vein. One nail.

The giant had one vein. One nail closed it.

The name is from the bronze giant that circled Crete. He was not beaten by something stronger. Someone knew where the nail was. Most agents are built strength first, brake afterwards. I built this one the other way around.

/stop

Aborts the running thought and clears the queue. No model, no thinking round — pure control.

/undo

Rolls back the last successful file change.

/autonomy 0

Shortens the leash to nothing. DENY stands on every level — this one adds refusal on top.

/log

The last events that had effect — written before the effect, not after.

These run deterministically, with no language model in between. A brake that has to think first is not a brake. A model that is hallucinating cannot prevent its own shutdown.

known limits

Known limits

A security claim without its limits is marketing. These are mine, up front.

  • The shell needs a sandbox the platform can provide. bubblewrap on Linux, sandbox-exec on macOS. Where neither exists it refuses rather than running unprotected.
  • It is not a multi-tenant security boundary. One operator, one machine.
  • It does not defend against a malicious model. It defends against a mistaken one, and against injection arriving through tool output. Different threats.
  • Every way in has to fetch, never receive. Telegram long-polls, mail is pulled over IMAP — nothing opens a listening socket. A From: header is only a claim; unauthenticated mail gets ask-only trust — it may ask, it may never approve.
